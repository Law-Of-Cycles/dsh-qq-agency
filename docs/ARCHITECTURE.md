# 设计说明

这份文档解释**为什么这么拆**，以及改行为时该动哪一块。

## 一、五层，各管一件事

```
lib/mind.js    内心：状态 + 算术。纯函数，无 IO，可单测。
lib/task.js    任务：一件要做几分钟的事的状态机。纯函数，无 IO，可单测。
lib/qq.js      嘴和耳朵：OneBot 11 HTTP。不抛异常。
lib/phone.js   身体：ADB。不抛异常。
lib/host.js    胶水：配置、心跳、决策执行、工具、路由、提示词。
lib/client.js  设置页：只读宿主那几条路由。
```

**为什么把内心做成纯函数**：因为"像不像活的"这件事必须能被验证。
`推进内心(心, 输入, 配置, 随机源)` 输入相同、随机源相同，输出必须逐位相同 ——
`tests/mind.test.mjs` 里那条"可复现"就是在守这个。

`mind.js` 不 import 任何东西，也不碰 `fs`。它不知道 QQ 存在，也不知道手机存在，
只知道"过了多少分钟、群里有多少条新消息、主人多久没说话、手机还亮着吗"。

## 一之二、为什么要单独一层「任务」

原来的心跳是「冲动 → 说一句 → 完事」，一句话就结束了。
但「去拼多多买个玩偶」不是一句话：要问许可、要挑、要再确认、要下单，
中间隔着好几分钟，用户随时可能改主意。

这种「跨多个心跳、跨多次 followup、还能被人中途叫停」的东西需要状态，
而且状态必须落盘（`tasks.json`）—— 否则宿主一重启，"等用户点头"这件事就丢了，
用户回来会发现它装作没问过。

`task.js` 跟 `mind.js` 一样是纯的（不读盘、不发网络、不看时间），
好处是所有关于"该不该花钱"的判断都能直接单测 —— 而这正是最不能出错的地方。

### 两段式确认：这次设计里最要紧的一条

同款耳机从 89 到 429 都有。如果用户随口一句「可以」就等于「花多少钱都行」，
模型自己挑一个 429 的，用户也只能认。

所以意图被拆成两档：

| 用户说 | 判成 | 含义 |
|---|---|---|
| 可以 / 行 / 好 / 去吧 / 看看 / 你看着办 | `批准` | 允许你**去看** |
| 买吧 / 下单 / 就它 / 确认 / 买 | `确认` | 允许**花这一笔** |
| 算了 / 别买了 / 不要了 / 停下来 | `取消` | 立刻停，优先级最高 |

状态机保证「批准」最多把任务推到 `找商品`，**到不了** `下单中`。
这条规则有专门的测试守着（`tests/flow.test.mjs` 的 ③）。

三道额外的闸：

1. **超预算的商品不拿来问用户** —— 直接拦掉换一个，别让人看见一个买不起的东西；
2. **确认时再核一次价** —— 防模型报错价（说 39 实际 429）；
3. **取消不可复活** —— 取消之后再说「可以」也不会重新开始。


## 二、内心状态

```js
{
  精力: 0..1,       // 向"这个钟点该有的精力"回归，时间常数 90 分钟
  无聊: 0..1,       // 没动静 +dt/45 分钟爬满；热闹就减；被点名直接 ×0.35
  想念: 0..1,       // 目标 = min(1, 缺席分钟/360) × 夜念权重；向你刚说话 ×0.45
  情绪: { 愉悦: -1..1, 唤醒: 0..1 },   // 愉悦向 0 半衰 2h，被点名/被叫 +0.2~0.3
  上次群发言, 上次私聊主人, 主人最后说话, 群最后热闹,
  今日: { 日期, 群发言, 私聊主人 },     // 跨天自动归零
  累计: { 心跳, 群发言, 私聊主人, 玩手机, 忍住 },
  念头: [{ 时间, 话 }]                  // 最多 30 条
}
```

`dt` 夹在 0–240 分钟：机器休眠一夜后不会一次跳成超新星。

### 冲动公式

```
群插话 = 0.30·无聊 + 0.28·热闹 + 0.55·被点名 + 0.15·话题命中 + 0.08·精力
         − 0.55(冷却中且未被点名) − 0.55(免打扰)
找主人 = 0.55·想念 + 0.20·无聊 + 0.12·精力 − 0.25(主人刚说话)
         − 0.60(冷却) − 0.55(免打扰) − 1.00(到当日上限)
玩手机 = 0.45·无聊 + 0.22·(1−精力) + 0.18·息屏 − 0.25·热闹 − 0.25(免打扰)
```

- **门槛** `= 0.72 − 主动性/100 × 0.34`；被点名时再降 0.18。
- **抖动** `± 0.06 × (0.6 + 主动性/125)`，让它在两个差不多高的选项之间偶尔选次优的那个。
- **冷却只压"主动插嘴"**：刚说完话又被点名，照样要应 —— 人不会装作没听见。

`热闹 = clamp(新消息/8)·0.75 + clamp(发言人数/5)·0.25`（取最热闹的那个群）。

## 三、两条路径：确定性回应 vs 自发行为

心跳里先处理**确定性回应**，再处理**自发行为**。这个顺序是有意的：

```
心跳
 ├─ 主人私聊有新消息（且 私聊直达 开）→ 转进会话，回他          ← 不看心情
 ├─ 某个群「提到我」（且 群被叫直达 开）→ 转进会话，回一句       ← 不看心情
 └─ 推进内心 → 决定
      ├─ speak_group → 构造独白 → 转进会话 → 发到群
      ├─ dm_owner    → 构造独白 → 转进会话 → 发到私聊
      ├─ use_phone   → 自己调 adb（通知/电量）→ 值得说才转进会话
      └─ idle        → 记流水，什么都不做
```

"被叫"不参与概率竞争：如果它也走冲动，就会出现"人被 @ 了但今天不想说话"的荒唐结果。

## 四、消息闭环（最容易出错的一段）

```
host.让它开口()
  → 待发队列 push({ 类型, 目标, 来由 })     // 按会话分队列
  → agent.followup(独白, source: {kind:'plugin', plugin:'qq-agency'})
       ↓ 模型跑一轮
  → session/event: assistant/message  → 本轮文本 = 正文
  → session/event: turn/end           → 队列 shift → 发到 QQ → 更新内心计数
```

三个坑，都在代码里写了注释：

1. **`followup` 必须 `await`**。它的 rejection 没接住就是未处理的 Promise rejection，
   能把整个 DSH 宿主带下去。失败时要把刚 push 的占位弹回去，否则队列错位。
2. **待发必须是队列，不是单个槽**。"被点名"和"自发插话"可能在同一轮心跳里都排上，
   用单槽会互相覆盖，第二句话就丢了。
3. **`turn/end` 要检查 `reason.kind === 'completed'`**。被中断的轮次里那段半截文本不该发出去。

`source` 标成 `{ kind: 'plugin', plugin: 'qq-agency' }`，不冒充用户亲手打的字。

## 五、和 dsh-qq-bridge 的边界

| | dsh-qq-bridge | 本插件 |
|---|---|---|
| 定位 | 通道：DSH ↔ QQ 双向转发 | 能动性：没人叫它时它做什么 |
| 触发 | 每一轮 | 心跳 + 被点名 |
| 会往 QQ 发 | 是（每轮最后一句） | 是（被叫的回应 / 自发的独白） |
| 冲突 | 同会话同开 = 双发 | 同左 |

插件之间没有互相让路的机制（也拿不到对方的开关），所以只能在 README 里讲清楚：
**二选一，或者盯不同会话。**

## 六、工具

注册给模型的工具分两组：

- **自我**：`agency_state`（读状态）、`agency_note`（记念头）、`qq_speak`（主动发一句）
- **身体**：`phone_status / phone_ui / phone_tap_text / phone_look / phone_tap / phone_swipe / phone_type / phone_key / phone_open / phone_notifications`

`phone_look` 要把图交给模型看，但工具的 `render` 是**同步**的，而 `attachments.admitPromptContent`
是异步的 —— 所以在 `execute` 里先把图片块备好、存进 `截图缓存`（路径 → content block），
`render` 只做同步查表。宿主没有 `attachments` 服务时降级成只给路径，不报错。

工具用**原始 JSON Schema** 注册（`ctx.tools.register({ name, description, parameters, output, execute })`），
不 import `@deepseek-ai/dsh-tools` —— 插件因此零运行时依赖，装的时候不会因为解析不到内部包而挂。

### 为什么「看界面」比「截图」重要

只给截图有两个死穴：纯文本模型根本看不见图；多模态模型看得见但**点不准**（只能估坐标）。

`uiautomator dump` 给的是**可点的文字 + 中心坐标**，这才是能真正操作 App 的东西。
所以 `phone_ui` + `phone_tap_text` 是主力，`phone_look` 只在自绘页面上当降级手段。

### uiautomator 的两个真机坑（都踩过）

**坑一：dump 会挂死。** 某些自绘页面（拼多多商品详情页/订单页）`uiautomator dump` 会卡在
futex 上永远不返回。只靠 adb 客户端的超时**不够** —— 客户端被杀掉后，手机端那个 uiautomator
进程会变成孤儿，继续占着 dump 锁，于是**后面每一次 dump 都超时**，整台手机看起来"坏了"。

对策：用手机自带的 `timeout 8 uiautomator dump …` 包住，让**手机端**自己到点杀掉。
再配一个 `pkill -f uiautomator` 兜底清理。

**坑二：退出码拿不到。** `adb shell` 不把退出码放进 stdout，而 `sh -c '…; echo $?'` 又不行 ——
adb 会把 argv 用空格重新拼一遍，引号会丢（实测变成 `timeout: Need 2 arguments`）。
所以 `跑()` 直接返回 `码`（从 execFile 的 `error.code` 取），靠它区分：

- `124` → 手机端 timeout 生效 = **这页根本 dump 不动**，立刻放弃，别重试（否则白等 30 秒）
- 其他失败 → 页面还在加载，重试有意义

### 拼多多实测结论

| 页面 | `phone_ui` | 说明 |
|---|---|---|
| 首页（HomeActivity） | ✓ 40–60 元素 | 商品卡片是可点的 ViewGroup，**标题文字本身不可点** |
| 搜索页 / 结果列表 | ✓ 35–49 元素 | 价格、销量都能读到 |
| 系统设置 | ✓ 19–40 元素 | 按文字点「存储」能进下一层 |
| 商品详情页 | ✗ 页面读不出来 | 自绘界面，dump 卡死；只能截图 + 坐标 |
| 确认订单页 | 时好时坏 | 早期能读到（92 元素，含"发起拼单"），完全渲染后读不到 |

**教训**：`phone_ui` 返回 `页面读不出来` 不是 bug，是这类 App 的真实边界。
模型看到这个字段就该换策略（截图 + 坐标），而不是反复重试。

## 八、落盘

```
<DSH_HOME>/qq-agency/
  config.json    设置
  mind.json      内心（每次心跳写一次，很小）
  tasks.json     手上那件事的状态（跨重启，别删 —— 删了它会忘掉问过你什么）
  groups.json    群列表缓存（设置页勾选用）
  journal.jsonl  每次决策一行：动作、分数、理由、三个冲动、状态
  shots/         手机截图（用完即弃，保留最近 12 张）
```

`journal.jsonl` 是"回头看它那天在想什么"的唯一依据，别删。
`tasks.json` 里只有**当前一个**任务 —— 同时办多件事会让人分不清它在说哪一件。

## 九、给"软件本体"和"手机版"留的口子

这个插件是**三层里最上层的"能动性"**，下面两层（IM 通道、身体）都被隔离成了可替换的接口。
以后要做独立本体或手机版，照这三条接：

| 以后要做 | 现在就可以照抄的接口 |
|---|---|
| **独立软件本体**（不要 DSH 也能跑） | `mind.js` 和 `task.js` 完全不依赖宿主 —— 它们只吃 `{ 现在, 群们, 主人, 手机 }` / `{ 类型, 现在, 商品, 说 }`、吐 `{ 心, 决定 }` / `{ 任务, 说话, 要问 }`。搬过去只要自己实现"心跳循环 + 说话落地 + 把模型的操作结果喂回状态机"三件事，`host.js` 的 `心跳()` 和 `收尾推进()` 就是现成的流程图。 |
| **手机版**（跑在手机上，本体就在设备里） | `phone.js` 的每个方法都对应一条 adb 命令，手机上换成 `Runtime.exec` / `InputManager` 是同一套语义。`phone_look` 的"截图 → 交给模型看"换成直接拿 `Bitmap`。 |
| **换 IM** | 照着 `qq.js` 的七个方法（`登录信息 / 发私聊 / 发群 / 拉私聊 / 拉群 / 拉群列表 / 调用`）写一个新实现，`host.js` 里换掉 `拿QQ()`，其余一行不用动。 |

三条共同的约束，别破坏：

1. **内心和任务都是纯的**。一旦它们开始读文件、发网络请求，"像不像活的"和"该不该花钱"
   就都再也测不了了。
2. **说话是两段**：插件决定"要不要说"，模型决定"说什么"。别把台词写进插件 —— 写死了就不像人。
   唯一的例外是状态机的确认语（"好，不弄了"），那是**行为确认**不是台词，可以固定。
3. **默认安静**。总开关默认关、试运行默认开、允许办事默认关。任何新增行为都先走这条闸。
